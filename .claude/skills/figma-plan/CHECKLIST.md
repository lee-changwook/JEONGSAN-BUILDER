# 계획서 품질 검증 체크리스트

계획서 작성 완료 후, 아래 항목을 모두 검증한다.
실패 항목이 있으면 수정 후 재검증. 모든 항목 통과 시 저장.

## 완전성 검증

- [ ] 모든 Figma UI 요소가 컴포넌트 분해 테이블에 매핑되었는가
- [ ] 스크린샷이 포함되어 시각적 기준점이 있는가
- [ ] 디자인 토큰 매핑 테이블이 빠짐없이 작성되었는가
- [ ] 에셋 URL이 누락 없이 기록되었는가

## 구현 가능성 검증

- [ ] 모든 컴포넌트에 파일 경로가 지정되었는가
- [ ] 구현 순서가 의존성 역순을 따르는가
- [ ] 각 구현 단계에서 "무엇을 만드는지"가 명시되었는가
- [ ] 모호한 표현("적절히", "필요에 따라", "등" 등)이 없는가

## 컨벤션 비종속 검증

- [ ] 특정 스타일링 라이브러리명(Emotion, Tailwind, CSS Modules 등)이 하드코딩되지 않았는가
- [ ] "스타일 파일", "디자인 토큰"처럼 추상적 용어를 사용했는가
- [ ] 프로젝트 컨벤션 참조가 필요한 곳에 "CLAUDE.md 참조" 안내가 있는가

## 참조 대조 검증 (figma-reference-plan 전용)

이 섹션은 figma-reference-plan으로 작성한 계획서에만 적용.

- [ ] 참조 코드의 스타일링/상태관리 패턴이 파악되었는가
- [ ] 재사용/변경/신규 분류가 빠짐없이 되었는가
- [ ] 변경 항목에 "무엇을 왜 바꾸는지" 이유가 있는가
